# 112 - Late carrier reintroduction no-go

Status: bounded no-go / downstream repair guard, 2026-06-11. This
generalizes the late-scale insertion and free-weight failures to the
S3/LT76 carrier route: carrier data added after a shadow trace package
is already formed cannot repair carrier selectivity.

## 1. Purpose

Docs 108-111 handle broad shadow-functorial overreach, relabeled first
maps, and strict prefixes that forget their primitive field downstream.
The remaining cheap repair is:

```text
form M_C, F_C, Tr_L, or a traceable object in a shadow category;
then reintroduce alpha, v, depth, ell, mu_C, Euler factorization, or
graph-depth through a weight, codomain, normalization, second map,
regularization, or comparison rule.
```

This document rejects that late repair. If carrier data were not
load-bearing before the trace package existed, adding them later is
readout or calibration, not carrier/effectivity death.

## 2. Late-Reintroduction Hypotheses

Let a proposal first form a trace package:

```text
P_sh = M_sh, F_sh, Tr_L(F_sh), or a traceable object
```

in a shadow-stable category. Say it has late carrier reintroduction if
all of the following hold.

```text
H112.1 shadow package first
  P_sh is formed before any map requires alpha, v, depth, ell, mu_C,
  Euler factorization, or graph-depth as primitive object data. Erasing
  any later carrier addition leaves the same typed shadow package and
  the same trace theorem.

H112.2 control package formable
  Epstein or DH controls can form the same typed P_sh. One valid
  control branch is enough, but the branch must be named.

H112.3 carrier data enters after P_sh
  Carrier fields are introduced only after P_sh exists, through a
  label, filter, restriction, weight, window, bilinear form, stress
  parameter, determinant presentation, codomain, normalization,
  density, quotient choice, regularization, second map, positivity
  convention, or comparison rule.

H112.4 no pre-trace carrier obstruction
  No carrier/effectivity map before P_sh makes the selected control
  structurally unformable.

H112.5 same theorem already spent
  The theorem that licenses traceability, properness, determinant,
  index, codomain, or trace value applies to P_sh before the late
  carrier data is added.

H112.6 late field not frozen as source data
  The late carrier field is not part of the zero-free source record for
  P_sh; it is selected as a downstream parameter, readout, or
  normalization.
```

## 3. Lemma

### Lemma 112.1

Under H112.1-H112.6, the proposal fails carrier selectivity and cannot
repair S3 or LT76 by late carrier reintroduction.

Verdict:

```text
REJECT_LATE_CARRIER_REINTRODUCTION
  carrier data enters only after the shadow trace package exists.

REJECT_POST_TRACE_DECORATION
  carrier data decorate, filter, weight, normalize, regularize, or
  choose a codomain for an already formed trace package.

REJECT_SHADOW_PACKAGE_FIRST
  the first load-bearing package is shadow-stable and control-formable.

REJECT_CARRIER_OVERREACH
  the same typed pre-reintroduction package is formable for Epstein or
  DH controls.

REJECT_FREE_WEIGHT
  the late carrier-sensitive datum is a supplied weight, form, window,
  stress, determinant wrapper, regularization, or codomain.

REJECT_FREEZE
  the late datum is selected after zero-side comparison or without a
  zero-free supplier.
```

### Proof

By H112.1, the first load-bearing package is formed in a shadow-stable
category before primitive carrier data is required. By H112.2, the
selected control can form the same typed package. Thus doc 87's required
carrier/effectivity death has not occurred at the first load-bearing
stage.

By H112.3-H112.5, the later carrier data is appended after the trace
package and its licensing theorem already exist. This cannot change the
fact that the theorem admitted the control through the load-bearing
stage. The late carrier datum may define a diagnostic, normalization,
or readout, but it is not the source of the trace package.

If the late datum is a chosen weight, form, window, stress,
regularization, determinant wrapper, or codomain, doc 93 applies. If it
is selected without a zero-free source record, doc 91 applies. If it is
merely an added scale/address parameter, doc 80 is the A1 instance of
the same failure.

Therefore late carrier reintroduction cannot repair carrier
selectivity. QED.

## 4. Decision Test

For any proposed repair, ask:

```text
F112.1
  What is the first traceable package P?

F112.2
  Was P formed before alpha/v/depth/ell/mu_C/Euler-factorization or
  graph-depth data became primitive object data?

F112.3
  Can Epstein or DH controls form the same typed P?

F112.4
  Where is the carrier field first used: before P, inside P, or after
  P?

F112.5
  Is the carrier-sensitive datum a theorem-forced source field, or a
  downstream weight/form/codomain/normalization/regularization?

F112.6
  Was the datum frozen by a zero-free supplier before first zero
  contact?
```

If F112.1-F112.4 show that P is shadow-stable before carrier data
enters, record `REJECT_SHADOW_PACKAGE_FIRST`,
`REJECT_LATE_CARRIER_REINTRODUCTION`, or `REJECT_CARRIER_OVERREACH`.
If F112.5 is downstream-supplied, record
`REJECT_POST_TRACE_DECORATION` or `REJECT_FREE_WEIGHT`. If F112.6
fails, record `REJECT_FREEZE`.

## 5. Covered Patterns

The no-go covers:

```text
adding log p, valuation depth, or Euler-factor labels after a trace
value is computed;
choosing a carrier-sensitive codomain after a shadow trace theorem
already applies;
post-composing a shadow trace with a valuation/depth readout;
regularizing a shadow determinant by a carrier-dependent parameter;
selecting a second carrier map after M_C or F_C already exists;
using a strict first map only to choose a later weight or normalization
after the trace package has forgotten it.
```

## 6. Non-Coverage

This no-go does not apply if:

```text
1. the carrier field is primitive object data before the trace package
   exists;
2. the trace theorem is stated on the carrier-dependent object, not on
   a shadow package;
3. the selected control cannot form the same typed package at the first
   load-bearing stage;
4. the carrier-sensitive codomain/form is theorem-derived before
   evaluation;
5. all load-bearing choices are frozen before zero contact.
```

Those are exactly the strict doc-98/doc-103/doc-111 live conditions.

Late carrier data can still be meaningful as diagnostics,
normalizations, or calibration. The no-go says only that they cannot
supply carrier selectivity for a package already formed in a
shadow-stable category.

## 8. Use Rule

Use doc 112 whenever a proposal says, in effect:

```text
first form the trace object;
then insert the carrier field that makes it selective.
```

That order is not B1 carrier selectivity. It is calibration, readout,
or post-processing unless the carrier field was already primitive and
load-bearing before the trace package existed.
