# 615 - Qbar_BECD FIdx24 Existing Primitive Morphism-Reuse No-Go

## Status

No-go theorem with a named mechanism. Layer I only; this is not an RH result.

## Claim

The doc-614 singleton residual obstruction cannot be repaired by interpreting
existing doc-610 reusable primitive feature conjunctions as morphism-level
reuse.

The named mechanism is **mixed-support morphism selector dilemma**.

## Setup

Doc 614 leaves only a narrower categorical route: abandon reused
boundary-surface states and ask for morphism-level reuse with proof-relevant
evidence. This witness tests the strongest such route available from existing
doc-610 data.

A candidate existing primitive morphism skeleton is any nonempty conjunction of
doc-610 reusable primitive features whose support:

```text
contains the singleton residual surface;
has size at least two.
```

Three profiles are tested:

```text
all features;
non-generic features, excluding boundary, event kind, and namespace;
segmental features only.
```

## Obstruction

For both singleton residual surfaces from doc 614, every reused
primitive-conjunction skeleton is mixed-class. There is no reused class-pure
skeleton.

For `entry_boundary:obstruction:external_or_oracle`:

```text
all features:        16407 reused skeletons, 0 class-pure
non-generic:          8191 reused skeletons, 0 class-pure
segmental:            8191 reused skeletons, 0 class-pure
```

The best non-generic skeletons already mix three classes:

```text
boundary_externality
action_semantics
classifier_partition
```

For the `not_source_internal` escape boundary:

```text
all features:           18 reused skeletons, 0 class-pure
non-generic:             6 reused skeletons, 0 class-pure
segmental:               6 reused skeletons, 0 class-pure
```

The best non-generic skeletons already mix three classes:

```text
source_internality
source_constraint_invariant
trace_payload_route
```

Thus existing primitive morphism reuse supplies shared skeletons, but those
skeletons do not select the singleton residual class. Turning them into a
repair requires an extra selector, synthetic support, a class merge, or a
label/anchor change.

## Consequence

The surviving route is now smaller: it must add genuinely new proof-relevant
morphism evidence not generated by existing doc-610 primitive conjunctions, or
prove that every such addition is synthetic duplication, name lookup, stem
retuning, class collapse, or a doc-602 anchor change.
